# DHO1000 series: what was measured on a DHO1204

Status: every item below was measured on a DHO1204 at the bench with a from-scratch acquisition
bring-up (no stock software running while capturing, except where noted). It is enough to capture,
state and stream samples; it is **not** enough to drive a DHO1000 as a scope (§9). Notation as in
`acquisition-start.md`; "verified" means on the unit, "assumed" is an inference.

The code that goes with this page is `hal/src/dho1000/` — measured (`acq`, `afe`, `export`),
reconstructed from the stock library (`avg`, `counter`, `display`, `dvm`, `mask`, `record`,
`serialtrig`, `spu`, `trigger`, `zone`), stock data (`clock`) and datasheet-rated (`series`); none
of it is wired into `target::ACTIVE`.

## 0. Result in short

1. The DHO1000 belongs to the same board family as the DHO800/DHO900: RK3399 + Zynq over
   PCIe/XDMA, the same stock kernel module list, the same register vocabulary.
2. A from-scratch init plus a per-batch record/play handshake starts the acquisition without the
   stock software and yields clean captures: 1,000,000 samples at 10 MSa/s, 0 sample gaps, 0
   duplicate batches, 0 % rails.
3. Roll mode streams at `depth / (100 * s_per_div)` — 20 kSa/s at 0.5 s/div, 200 kSa/s at 0.05 s/div.
   **10 MSa/s is not reachable in roll mode.**; the record engine needs the batch handshake and
   runs ~1 MB/s synchronously, but the **app-free export handshake** (§4a) reads record pages of
   1 M frames at 12-20 MB/s with one blocking read each — that, not the batch loop, is the deep
   memory path a port should drive.
4. The front end takes a 14-range table (0.5 mV/div … 10 V/div); the absolute gain was not verified.
5. The stock kernel is 4.4.126 with `CONFIG_MODVERSIONS`, so a self-built module must carry the
   unit's symbol CRCs (recoverable from `/rigol/driver/*.ko`).

## 1. Board

Identical stock module list to the DHO800/DHO900: `xdma`, `pcie-rockchip`, `spi2afe_gpio`,
`spi2pll_gpio`, `fpga_gpio`, `hdcode_gpio`, `dac_gpio`, `beeper_gpio`, `pwm_fan`, `afe_rms_gpio`,
`focaltech_ts`, `ilitek_ts`, `motorcomm`, `usbtmc_dev`, `libcomposite`, `usb_gpib`.

- Stock kernel: `Linux 4.4.126 #58 SMP PREEMPT aarch64`, built by `adil@ubuntu` with Linaro GCC
  6.3.1; Android 7.1.2.
- XDMA: Xilinx XDMA Reference Driver **v2019.2.51** (`/rigol/driver/xdma.ko`), vermagic
  `4.4.126 SMP preempt mod_unload modversions aarch64`.
- Devices used: `/dev/xdma0_bypass` (BAR), `/dev/xdma0_c2h_0` (stream), `/dev/spi_simulate`
  (AFE SPI bridge; world-writable, SELinux disabled on the unit).
- Stock partition map from the kernel command line (`mtdparts`, sectors of 512 bytes):
  uboot 0x2000@0x2000, trust 0x2000@0x4000, misc 0x2000@0x6000, resource 0x8000@0x8000,
  kernel 0xC000@0x10000, boot 0x10000@0x1C000, recovery 0x20000@0x2C000,
  backup 0x38000@0x4C000, cache 0x40000@0x84000, system 0x400000@0xC4000,
  metadata 0x8000@0x4C4000, verity_mode 0x40@0x4CC000, baseparamer 0x2000@0x4CC040,
  frp 0x400@0x4CE040, rigol 0xFA000@0x4CE440, userdata from 0x600000.

## 2. Register vocabulary

Same names as the DHO800/DHO900 (`acquisition-start.md`, `record-play.md`, `roll-mode.md`):

| Register | Meaning (verified) |
|---|---|
| `0x4004` | control: bit0 run, bit31 stop, bit19 = arm one batch |
| `0x4008` | mode: bits 0-3 = channel mask, bit17 = roll, bit22 = scan |
| `0x400c` | record/play: bit28 trigger, bit29 play, bit30 run |
| `0x4010/0x4014/0x4018` | record positions (`0xf0/0/f0` live, `0xf0/0xf0/0xf0` while a batch is armed) |
| `0x4020` | bit0 = auto-trigger |
| `0x4068/0x406c` | record interval (`0` live) |
| `0x1010` | TX latch: pulse bit28 (clear → set → clear), bit31 = header on/off |
| `0x11e8` | TX fill level in 8-byte units after a pulse |
| `0x1000`-block | SPU: `0x1004` mode, `0x10d0/0x10d4/0x10d8` rate divider, `0x10e0` memory size, `0x10e4` depth, `0x105c` low byte 0x55 |

## 3. From-scratch init (verified)

Replaying the stock software's live register values from a snapshot does **not** restart the
stream (it stays at tx = 0); this init does:

```
0x4004 = (s4004 & ~1) | bit31          stop
0x4004 = s4004 & ~bit2                 abort clear
0x1000: pulse bit0, bit4, bit5, then bit0 again   (init, TX reset, preproc reset, init)
0x105c = (s105c & ~0xff) | 0x55
0x1010 |= bit29
0x10e0 = 0x00400000
0x10e4 = depth
0x1004 = s1004 & ~3                    normal mode
0x4008 = (s4008 & ~(bit17|bit22)) | mask
0x4068 = 0x406c = 0
0x400c |= 0x30000000
0x4010 = 0xf0, 0x4014 = 0, 0x4018 = 0xf0
0x400c = (s400c & ~bit28) | 0x60000000
0x4004 |= bit0                         run
```

## 4. Normal-mode batches (verified)

Per batch: `0x4004 |= bit19`, `0x400c = 0x60004000`, positions `0xf0/0xf0/0xf0`; the FPGA clears
bit19 itself after about **15 ms**; then pulse `0x1010` bit28, read `0x11e8` (tx) and read exactly
`tx * 8` bytes; finally `0x400c = 0xa2008000` and clear bit19.

Measured (1 Mpts, 10 MSa/s, one channel):

| quantity | value |
|---|---|
| batch | 7,692 samples (15,384 bytes), tx = 1,923 |
| cadence | 131 batches / 2 s ≈ **1 MB/s** synchronous |
| read size | must be `tx * 8`; larger reads stall (`stopped half-way`) |
| latch only (no bit19) after this init | 0 bytes |
| capture quality | 0 gaps, 0 duplicate batches, 0 % rails in 1 Mpts |

The stock software reaches 8–17 MB/s (rchar) from the same driver and char device, with its own
servicing; every attempt to reproduce that in userspace failed (replaying all readable live
registers included). One run reached 2,372 batches / 35.8 MB in 3 s (≈6 MS/s) by inheriting engine
state from a previous run; it was not reproducible. The batch loop is not the answer: the stock
software reads **whole record pages** through the SPU window registers with one blocking `read()`
per page, and that path was reproduced app-free (§4a).

## 4a. App-free record export (verified)

The validated page read-out (the sidecar's `rs_export`, run with the stock software dead):

1. freeze (`0x4020` bit 0 off, run bit off) and park the display chain: zoom off (`0x4008` bit 25),
   both compressors `(shadow & 0x30000000) | 0x40000001`, sinc `0x1130/0x1134 = 0x00010101`, both
   interpolators off with phases `0/0xffffffff`, then **`0x1004` bit 25 off and
   `0x1000 = 0x0400_0000`** — the two decisive writes;
2. the window in frames: `0x1108 = start`, `0x1100 = frames + 0x200` (the stock tail padding),
   `0x11f0 = frames`, `0x11e8 = frames / 8`;
3. the record-play handshake: positions zero, `0x400c` through arm/commit to
   `(1 << 29) | (shadow & 0x9bffffff) | 0x40000000`, the control pulses
   `0x4004 = 0x00080a00 -> 0x00000809`, the first SCU bundle (`0x4024..0x403c`:
   `0x00081001, 0x00801601, 0x00080605, 0x04c4a907, 0x00000007, 0x020a0601, 0x020a8601`),
   `0x4004 = 0x00100809`, the second bundle (`0x80081001, 0x00801701, 0x00080705, 0xcf04a90e,
   0x0000000e, 0x228c0701, 0x028c8701`), then arm bit 19;
4. one blocking `read(frames * channels * 2)` — little-endian 16-bit samples, channel-interleaved
   ascending; bit 19 re-armed per page; the saved registers restored at the end.

Measured: 1 Mpts pages at 10 MSa/s clean (10 pages per record); 4-channel records read as
interleaved quarter-pages. Implemented in `hal/src/dho1000/export.rs`.

## 5. Roll mode (verified 0.05 … 1.0 s/div)

Writes: `0x4008 = mask | bit17`, clear bit22; `0x4020 |= 1` (auto-trigger); `0x4004 |= 1`.

- No arming; the latch loop (pulse `0x1010`, read `tx * 8`) streams continuously in this mode.
- Rate is set by the time base: `rate = depth / (100 * s_per_div)`.

| time base | stream (1 Mpts record) |
|---|---|
| 1.0 s/div | 10 kSa/s |
| 0.5 s/div | 20 kSa/s |
| 0.2 s/div | 50 kSa/s |
| 0.1 s/div | 100 kSa/s |
| 0.05 s/div | 200 kSa/s |

A time base that implies more rate than the record holds leaves `0x4010 = 0x4014 = 0x4018` and
tx = 0 (measured with 100 kpts at 1 MSa/s).

## 6. Front end

`hal/src/dho1000/afe.rs`: 14 ranges (0.5 mV/div … 10 V/div), 13 registers each (same map as the
DHO800/DHO900 front end: `0x00,0x01,0x03,0x04,0x05,0x06,0x08,0x09,0x0a,0x0c,0x0e,0x11,0x12`), a
DAC base code at 0 V and a DAC LSB per volt (`lsb_per_v` negative on the 0.5 mV…50 mV ranges).

Not verified: the absolute gain. Writing the table on the unit made a ±1 V signal 13 px high at
1 V/div where the stock picture shows 189 px. A calibration against a reference is required before
these values can be used for measurements.

## 6a. Series model and rated limits (datasheet)

`hal/src/dho1000/series.rs` carries the model table and the rated limits from the DHO1000 Data
Sheet; none of it is measured on a unit except where it says so:

| | DHO1072 / DHO1102 / DHO1202 | DHO1074 / DHO1104 / DHO1204 |
|---|---|---|
| bandwidth | 70 / 100 / 200 MHz | 70 / 100 / 200 MHz |
| channels | 2 + EXT | 4 + EXT |
| sample rate | 2 GSa/s (1 on), 1 GSa/s (all) | 2 GSa/s (1 on), 1 GSa/s (2 on), 500 MSa/s (all 4) |
| memory (standard) | 50 / 25 Mpts (1 on / all) | 50 / 25 / 12.5 Mpts (1 / 2 / 4 on) |
| resolution | 12 bit (16 bit in high-resolution mode) | |
| graticule | 10 x 8 divisions | |
| V/div | 500 uV .. 10 V | |
| input | 1 MOhm, DC/AC/GND, **no 50 Ohm path** | |
| time base | 5 ns/div .. 1 ks/div | 2 ns/div .. 1 ks/div |
| roll from | 50 ms/div (or 100 ms/div selectable) | |
| scan from | 200 ms/div | |
| generator, logic analyser | none | none |

Two of these agree with what was measured here, which is a useful check on the table: the roll
threshold (50 ms/div) is exactly the time base at which the unit streamed roll samples (§5), and
the 500 uV .. 10 V range matches the recovered front-end table (§6). The optional 100 Mpts memory
is deliberately not assumed (`limits()` uses the standard depths).

Corrections and measurements against that table: every model has the EXT trigger input (the
datasheet's "2 + EXT / 4 + EXT"; `caps()` now sets it for all), the depths the stock software
offers are 1M/10M/25M/50M with 20M silently becoming 10M, and with all four channels on the unit
clamps to 10 Mpts rather than the datasheet's 12.5. The sample-clock chip is identified: an
LMK04821 behind the `spi2pll` boot step (§6c).

The front-end ladder (`afe::scale_ladder`, the same 1-2-5 steps as the DHO800/DHO900) is bounded by
500 uV .. 10 V and snaps into the 14 measured ranges; `afe::COUPLINGS` is DC/AC/GND, with
`SERIES::HAS_50OHM = false`.

## 6b. Reconstructed from the stock library

The stock acquisition library (`libscope.so`, the file the stock software loads) was decompiled; the
result is enough to write the register sequences without a unit at the bench. A second and third
round over the same decompilation decoded the pieces the first round left open: the full trigger
type dispatch and pattern word, the serial receivers, the counter, the mask table, the zone compare
tables, the record engine and the SPU configuration; two data tables were recovered from the stock
binary itself (`zoneChanMap`, `ToLogicSel`) and the clock table from the stock firmware image.
Addresses below are Ghidra addresses (file offset + 0x100000). **None of it has run on hardware
yet**: it is the stock software's own programming, reconstructed, not measured.

### Trigger (TPU block, 0x2000..0x22ff)

| Register | Use | Stock function |
|---|---|---|
| `0x2004 0x200c 0x20b8 0x20c0` | trigger-A threshold per channel, `lo \| hi << 16` | `DevSystemTPU_SetLevelA` @0x2af4c8 (table at file 0xa0af20) |
| `0x2008 0x2010 0x20bc 0x20c4` | trigger-B threshold per channel | `DevSystemTPU_SetLevelB` @0x2af4f0 (table at 0xa0af30) |
| `0x201c` / `0x2034` / `0x204c` | source + event word of A / B / R | `SetSourceA` @0x2af94c, `SetSourceB`, `SetSourceR` |
| `0x2020 0x2024 0x2028` | A event + two times (1 ns ticks, high halves packed at `0x2028`) | `SetTriggerA` @0x2afac4 |
| `0x2038..0x2040`, `0x2050..0x2058` | B / R time words | `SetTriggerB`, `SetTriggerR` |
| `0x2014 0x2018`, `0x202c 0x2030`, `0x2044 0x2048` | logic operations A / B / R | `SetLogicOperation*` |
| `0x205c` | trigger mode (bits 0-4), force, ABR FSM, SPU bypass | `SetTriggerMode` @0x2afce0 |
| `0x2060 0x2064` / `0x2068 0x206c` | delay / R timeout | `SetTriggerDelaytime`, `SetTriggerRTimeout` |
| `0x2070` / `0x2074` | ABR event numbers | `SetTriggerABREventANum/BNum` |
| `0x2080` / `0x2084 0x2088` | holdoff event number, time (4 ms units) and type (bits 16-18) | `SetTriggerHoldoffTime` @0x2afef4, `...Type` @0x2afed8 |
| `0x208c` | IIR filter: bits 0-1, 2-3, 4-17 | `SetTriggerIirset` @0x2aff64 |
| `0x2264` | EXT trigger hysteresis | `SetExtTrigHys` |

Threshold code: `(level + offset) * 7500 / (scale_nv * digital_gain) + 32768`, clamped to
1..0xfffe; noise rejection widens it to `level ± noise` (`DrvBaseTrigger_SetLevelAjx` @0x2e7ed8).

Analog channel N uses comparator inputs `2N-2` and `2N-1`: rising sorts them `(a,0,b,1)`, falling
`(b,1,a,0)`, "either" also programs the B side and sets mode 1 (`DrvBaseTrigger_applyCfg` @0x2e7724,
`ToTpuWhen` @0x2e87ec). AC-line and EXT sources map to `0x30` and `0x31`.

The pattern word is decoded: `SetSourcePatternA/B/R` @0x2af9dc/0x2afa64/0x2afa94 write bits 16-23
of the event register — slot-A source (16-18), slot-A invert (19), slot-B source (20-22), slot-B
invert (23) — so `SetSourcePatternA(2,1,2,1)` arms both slots as edge terms. The trigger-mux codes
of `0x205c` bits 0-4, from every `applyCfg` call site: 0 edge, 1 A+B, 3 Nth-edge, 4 UART, 5 IIS,
6 LIN, 7 CAN, 8 FlexRay, 0xa 1553B, 0xb SENT, 0xc SPI, 0xd I2C, 0xe TV. The ABR machine lives in
bits 6-10 (`SetTriggerABRFSM` @0x2afd5c) with the reset pulse on bit 11 and force on bit 5; the SPU
bypass is bit 12 (set for every serial type and the pattern trigger). `ToTpuWhen` @0x2e87ec maps the
UI when-codes {1..4} to 0-3, 0 to 5, anything larger to 6.

`DrvBaseTrigger_SetType` @0x2e759c dispatches the UI types (0 edge, 1 pulse, 2 slope, 3 TV,
4 pattern, 5 duration, 6 timeout, 7 runt, 8 window, 10 delay, 11 setup/hold, 12 Nth-edge, 0xd UART,
0xe I2C, 0xf SPI, 0x10 CAN, 0x12 FlexRay, 0x13 LIN, 0x14 IIS, 0x16 1553B, 0x18 SENT, 0x1d zone),
and each `applyCfg` is reconstructed as a composed function: `edge`, `edge_line`, `pulse`, `slope`,
`runt`, `window`, `timeout`, `delay`, `pattern`, `duration`, `nth`, `setup_hold` and `video`, the
last with the per-standard `SetVideoCfg2/3` constants the stock code hardcodes. Pattern and duration
share the 21-term logic block (`SetLogicOperation*` @0x2af518: 2-bit terms in `0x2014` spilling
into `0x2018`, the output op in bits 10-11; `ToLogicSel` LUT [2,3,0,0,0] recovered from the binary,
`toTpuLogicFun` 1->1, 3->2).

Implemented in `hal/src/dho1000/trigger.rs` with a host test per setter. Not decoded: the slope
trigger's own width limits (its `SetWhen` path), and the video constants beyond their values (what
the two 16-bit halves mean). The serial receivers moved to their own module (next section).

### Hardware averaging

`DevAcquireSpu_setAvgPara` @0x2a55bc: `0x10b0 = count - 1` (at least 1),
`0x1148 = 0x20 + 0x280 / channels`; `SetAvgSincMode` @0x2a559c sets bit 2 of `0x1004`;
`setAvgClr` writes `0x10b4`. Implemented in `hal/src/dho1000/avg.rs`.

### Display path: compression and interpolation

`DevAcquireSPU_SetCompress` @0x2a74fc: `0x1170` (main) / `0x1174` (zoom) get
`value & 0xfffffff | more_than_one_channel << 31 | shadow bits 28-29 | 0x40000000`.
`DevAcquireSPU_SetLinearInterp` @0x2a7334: `0x1154` carries one disable bit per path (0 main,
1 zoom), the phase step `((den << 32) - den) / num` (or `0xffffffff` when off) goes to
`0x1158/0x115c` (main) or `0x1160/0x1164` (zoom). `ConfigHorizontal` @0x2d962c drives both from the
time base and channel count. A frame that never completes is the chain state, as in the DHO800/900
`record-play.md`: the pass-through fix (both compressors `0x40000001`, both interpolators off) is
`display::passthrough()`. Implemented in `hal/src/dho1000/display.rs`.

### DVM

`DevAnalyzeDvm_SetDvm` @0x2b93b4 writes `0x2244` (bit 0 enable — written alone first as a soft
start — bits 1-5 mode, bits 8-9 the channel mux); a read latches `0x2248` and reads two
accumulators (`DevAnalyzeDvm_GetDvm` @0x2b9424): the 48-bit sum from `0x224c`/`0x2250` and the
64-bit sum of squares from `0x2254`/`0x2258`, each divided by `1 << shift` samples. The modes are
software (`DvmData::getDcRmsMaxMin`): DC is the mean, AC-rms the square root of the variance,
AC+DC-rms the root of the mean square. Implemented in `hal/src/dho1000/dvm.rs`.

### Zone trigger and mask output

`DevAcquireSPU_SetZoneTrigCtrl` @0x2b9fd8: `0x11d0` bits 24-27.
`DevAcquireSPU_SetMaskOutput` @0x2b9d9c: `0x119c` index in bits 2-23, enables in bits 29-31.
`DevSystemSCU_SetMaskZoneTrig` @0x2ba080: `0x4020` bits 12-15 and bit 1.

The single-zone compare table is decoded (`DrvZoneTrigger_makeSingleTab` @0x3053a8,
`DevAcquireSPU_SetZoneTab1/2` @0x2ba000): 1000 words per enabled table at `0x11d8`/`0x11dc`, each
`bank << 28 | column << 18 | in-zone << 16 | upper << 8 | lower`. The column decimates across the
interleaved ADC banks (`col = i / (4 / chan_count)`, bank = base + (i * step) mod 4 from the
`zoneChanMap` table, 44 rows recovered from the stock binary at file 0x00c12950); the in-zone flags
mark `rate * t1 + 1 .. rate * t2`; the vertical limits are `(limit + offset) * 7500 / scale`,
sign-flipped in bit 15. `SetZone1`/`SetZone2` @0x204bfc/@0x204e2c write the same settings block —
the two tables differ by channel and enable only. Implemented in `hal/src/dho1000/zone.rs`
(`make_single_tab`); the dual-zone geometry (`makeDoubleTab` @0x204e7c) is not decoded.

### Serial trigger receivers

Implemented in `hal/src/dho1000/serialtrig.rs` — the packings of the `DevSystemTPU_Set*` setters,
one composition per protocol:

| Protocol | Registers | Composition |
|---|---|---|
| UART | `0x2100` cfg1, `0x2104` cfg2 | R event, pattern (0,0,2,idle), mode 4; divider `1e15 / (baud * 4e6)` in bits 0-20 |
| I2C | `0x218c`-`0x21a0` | SCL on A, SDA on B, mode 0xd; three 10-bit timing fields (halved in 7-bit mode), 40-bit min/max/mask compares |
| SPI | `0x2178`-`0x2188` | clock on A, data on R, MISO on B, mode 0xc; CS/idle-timeout framing bit |
| CAN | `0x213c`-`0x2164` | R event, mode 7; six condition fields, the same divider + a 0.01-scaled sample position, ID and data compares |
| LIN | `0x2118`-`0x2138` | R event, mode 6; four condition fields, the CAN-style rate word, data compare |

Field meanings (condition, relation, parity, stop, width) follow the slot layout of the
DHO800/900 receivers — the same FPGA family keeps the field order. The packings of IIS, FlexRay,
1553B and SENT are located (`0x2108`-`0x2114`, `0x2168`-`0x2174`, `0x21b0`-`0x21bc`,
`0x21d0`-`0x21f0`) but not reconstructed.

### Frequency counter

`DevAnalyzeCnt_*` @0x2b8bdc-0x2b8f68, the 0x2200 block: init/compare words (both 0x8080), source
enable bit 0, per-channel nibble at `0x220c`, mode/gate/control bits at `0x2210`, the raw gate at
`0x2214`, the latch strobe `0x2218` and five 64-bit results (`0x221c`-`0x2240`: start, end, edge
count, single period, total events; bit 63 of the high words is the valid flag). The value
(`DrvCounter_GetValue` @0x306cd4) is a reciprocal counter on a 500 ns reference tick
(`TICK_FS = 5e5`): the period is `((gate_fs/TICK - start - end) / max(num - 1, 1)) * TICK`, falling
back to the single-period word below two edges; frequency is `1 / (period * 1e-15)`, period
`period * 1e-15`, totalize the event count. Implemented in `hal/src/dho1000/counter.rs`.

### Mask / pass-fail

`DrvMask_setMaskRule` @0x30a938 and `DevSystemSCU_setMaskRule` @0x2ba2a8: a 1000-column table of
8-bit limits, one write per column to `0x1194` — `column << 16 | lower | upper << 8 | 0xfc000000`,
the column field counting itself up. The 16-to-8-bit conversion rounds half up for positive values
(`(v + 0xff) >> 8`) and shifts negative ones as they are. Control `0x1190` (`SetMaskCtrl`
@0x2b9b38): channel nibble 24-27, latch bit 28 (cleared-set-cleared by `queryMaskReport`
@0x2ba320), clear-fails 29 and clear-frames 30 (both pulsed together by `ClearSum` @0x2b9bdc).
Counters: tested frames `0x11a0/0x11a4` (64-bit), per-channel fails `0x11b0`-`0x11cc`. Compress
`0x1184` (`SetMaskCompress` @0x2b9b24): samples per column in bits 0-27, enable bit 31. The SCU
side (`0x4020`): enable bit 15, save-pass 14, save-fail 13, stop-on-fail 12. Implemented in
`hal/src/dho1000/mask.rs`.

### Record engine and the auto-trigger watchdog

`DevSystemScu_SetRecordSeq` @0x2aea98 (arm `0x30000000`, frames at `0x4010/0x4014/0x4018` =
start/start/start+count-1, commit `0x22000000`), `SetRecord` @0x2aef7c, `setRecordPlay`
@0x2aeb8c, `setSeqPlay` @0x2af068 (interval written raw), `SetRecordSeqEn` @0x2af040 (bit 25);
interval `0x4068` and FSM timer `0x406c` in 4 ns ticks, the timer's bit 31 on overflow. Play state
`0x4080` (bit 30, clear pulse bit 31, frames done = `0x4010 - 0x4014 + 1`); per-record timestamps
strobe `0x40b8` bit 0 and read `0x40b0/0x40b4`; status `0x4034` bit 13 = stopped.

The piece the first round missed: `DevSystemSCU_SetAutoTrigger` @0x2af280 writes the auto-trigger
bit of `0x4020` and a watchdog pair `0x4060` (timeout) / `0x4064` (holdoff) in 4 ns ticks. The stock
FSM derives them from the time base — timeout = tdiv x 20 clamped to 10..200 s, holdoff = max(trigger
holdoff, timeout / 2) with a 5 s floor. **Without them the record engine produces one record and
stalls** — the stall the first takeover attempts saw. Implemented in
`hal/src/dho1000/record.rs`.

### SPU configuration

`DevAcquireSPU_SetSampleRate` @0x2a56a8: below 250 MSa/s the slow divider `0x10d8 =
250 MSa/s / rate` (25 at the measured 10 MSa/s); at or above, `0x10d0 = (2 GSa/s / rate) & 0xff |
0x8000` (0x8004 at the measured 500 MSa/s) and `0x10d8 = 1`; `0x10d4` is always 0.
`SetAcqMode` @0x2a5558: average = bit 1, high resolution = bit 3 of `0x1004` (sinc = bit 2, see
`avg`); hires engages below one eighth of the maximum rate. `SetMemSize` `0x10e0`, record depth
`0x10e4`, anti-alias `0x10dc`, pre-sample compensation `0x404c` (5, or 15 in average mode), sample
range `0x4050/0x4054`, record-sum status `0x1208`. The stock `ConfigAcquire` order is in the module
doc. Implemented in `hal/src/dho1000/spu.rs`.

### Sample clock: an LMK04821

The sample clock is **identified**: an LMK04821 jitter cleaner behind the stock `spi2pll` kernel
module, initialised at boot from `resource/conf/init_all_clock.txt` in the firmware image (129
register words, recovered verbatim into `hal/src/dho1000/clock.rs`, ending in the VCO calibrate
word 0x53). The stock library adjusts it at run time through `Dev_LmkWrite` ioctls:
`DevBoardClock_SetAFEChanFrequency` @0x2ae56c writes `2e9 / freq` into register 0x130 or 0x100 per
AFE channel (a 2 GHz VCO), `DevBoardClock_AFEChanOutput` @0x2ae4e0 turns an output on/off (0xf8/
0xf0 into 0x136 or 0x106). The table is stock data; driving it from OOS needs the `spi2pll`
interface, not FPGA writes. The chip identity is verified on the unit (boot log).

### Where the rest is

Still not reconstructed: the self-calibration pipeline (`CApiCal::processSelfCal` @0x34c368 and
the `CCalibration_*` classes — entry points clear, the iterative loops heavy), the front panel
(not in this library), the calibration-file payload layouts (the container is the stock
`CCheckedStream`, same family as the DHO800/900 `calfile`), and the SPU coefficient RAM
(`configDspCoef3` @0x2a62c0 writes the sinc filter bank through `0x109c`; the coefficients are
computed elsewhere).

## 7. Stock kernel modules (for reference)

`CONFIG_MODVERSIONS` is on, unsigned modules load, and the unit's symbol CRCs can be harvested from
the `__versions` sections of `/rigol/driver/*.ko` (339 symbols over 18 modules, no conflicts).
Config/ABI differences are not benign: a module built without `TRACEPOINTS` loaded and then
panicked in `trace_module_notify` (struct module layout), rebooting the unit. A safe probe is to
compare `.rela.gnu.linkonce.this_module` offsets against a vendor module (init at 344, exit at 752
for this kernel).

## 8. Tools used

`sidecar` (BAR dump/write, from-scratch takeover with `--record-loop`), the sidecar library's
`rs_export` (the validated page read-out of §4a), a per-batch timing probe, and `memscan`
(process_vm_readv of the stock `CDrvScope` fields: rate `0x2b18`, depth `0x2b48`,
record count `0x2b78` = 240), plus the Ghidra decompilation cache of `libscope.so` the
reconstructions of §6b cite.

## 9. Missing before a DHO1000 image can drive hardware

Measured on the unit (`acq`, `export`'s handshake), reconstructed from the stock library and
binary (`avg`, `counter`, `display`, `dvm`, `mask`, `record`, `serialtrig`, `spu`, `trigger`,
`zone`, the clock and LMK tables, the front-end gain), rated from the datasheet (`series`). What
remains, each item needing the unit at the bench:

- **On-unit validation** of every reconstructed sequence above: they are the stock software's
  programming, faithfully reproduced and host-tested, but none has run as OOS code.
- The **FPGA start**: bitstream load over SPI (`DevBoardFpga_Download` @0x2b9938 shows the stock
  path: a K7 GPIO handshake plus 49 MHz SPI; the images and board-version map are in the stock
  firmware) and the ADC/lane set-up around it (deskew, IDELAY eye scan, core alignment — the
  DHO800/900 equivalents are `hal/src/dho/boot/`).
- The **front panel** (not in `libscope.so`) and the board monitor (fan, temperatures — thin
  wrappers around kernel ioctls).
- The **calibration files** in `/rigol/data`: the container is the stock `CCheckedStream`, the
  payload layouts are only partly located (the vertical-calibration rows were read from the running
  stock process by the sidecar tools), and the self-cal pipeline is not reconstructed.
- The `spi2pll` interface for the LMK04821 (the table is recovered; the kernel-side programming
  is not).

The family gate stays closed while all of this is unverified: `model::other_family` identifies a
DHO1000 and `drives_hardware()` stays false, as before.
